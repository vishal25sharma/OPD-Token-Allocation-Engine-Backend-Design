# OPD Token Allocation Engine - Documentation

## 1. Overview
The OPD Token Allocation Engine is an API-based service managed by Node.js and Express. It manages doctor appointments with:
- **Hard Slot Limits**: Slots have fixed capacity (elasticity via preemption, not overbooking).
- **Dynamic Reallocation**: High-priority tokens (Emergency) preempt pre-booked lower-priority tokens.
- **Waitlist Management**: Displaced or rejected tokens are queued and automatically reallocated when slots free up.

## 2. Prioritization Logic
The system uses a strict priority score for token sources:
| Token Type | Priority Score | Description |
|---|---|---|
| **EMERGENCY** | **50** | Highest priority. Can preempt any lower priority token. |
| **PAID** | **40** | Priority access. |
| **FOLLOWUP** | **30** | Returning patients. |
| **ONLINE** | **20** | Standard online booking. |
| **WALKIN** | **10** | Lowest priority. First to be preempted. |

### Preemption Algorithm
When a slot is FULL:
1. The new token's priority is compared against the *lowest* priority token currently in the slot.
2. If `New.Priority > Lowest.Priority`:
   - The **Lowest** token is removed (Preempted) and moved to the **Waitlist**.
   - The **New** token is inserted into the slot.
3. If not, the New token is added to the Waitlist directly.

### Cancellation & Reallocation
When a token is cancelled:
1. It is removed from the slot.
2. The system immediately scans the **Waitlist** for the highest-priority token that fits the slot.
3. If a match is found, it is automatically moved from Waitlist to Active Slot.

## 3. API Endpoints

### `POST /api/doctors`
Initialize a doctor and their slots.
```json
{
  "id": "doc1",
  "name": "Dr. Strange",
  "slots": [
    { "id": "slot1", "startTime": "09:00", "endTime": "10:00", "capacity": 2 }
  ]
}
```

### `POST /api/book`
Book a token.
```json
{
  "doctorId": "doc1",
  "slotId": "slot1",
  "patientName": "John Doe",
  "type": "WALKIN" // Options: EMERGENCY, PAID, FOLLOWUP, ONLINE, WALKIN
}
```
**Response**:
- `201 Created`: Allocated successfully.
- `202 Accepted`: Added to Waitlist (Slot full and no preemption possible).

### `POST /api/cancel`
Cancel a token.
```json
{ "tokenId": "12345" }
```

### `GET /api/doctors/:id`
View current schedule and slot status.

## 4. Edge Cases & Failure Handling
- **Double Booking**: The system prevents allocating the same token ID twice (though currently generated by timestamp, in DB usage unique constraints would apply).
- **Slot Capacity**: Hard limits are enforced. The array length never exceeds capacity.
- **Race Conditions**: In this in-memory implementation, JS event loop single-threading prevents race conditions. In a distributed DB system, transactions (ACID) would be required during `allocate` and `preempt` steps.
- **Waitlist Starvation**: Low priority tokens (Walk-ins) might stay in waitlist indefinitely if high priority tokens keep arriving. A "aging" mechanism (increasing priority over time) could be a future enhancement.

## 5. Manual Booking Instructions (Testing)
You can manually book tokens using `curl` commands in your terminal while the server is running.

### 1. Initialize a Doctor
```bash
curl -X POST http://localhost:3000/api/doctors \
  -H "Content-Type: application/json" \
  -d '{
    "id": "doc_manual",
    "name": "Dr. Manual",
    "slots": [
      { "id": "s1", "startTime": "10:00", "endTime": "11:00", "capacity": 2 }
    ]
  }'
```

### 2. Book a Token (Change `type` as needed)
**Types available**: `WALKIN`, `ONLINE`, `FOLLOWUP`, `PAID`, `EMERGENCY`.

**Walk-in Booking**:
```bash
curl -X POST http://localhost:3000/api/book \
  -H "Content-Type: application/json" \
  -d '{
    "doctorId": "doc_manual", 
    "slotId": "s1", 
    "patientName": "John Walkin", 
    "type": "WALKIN"
  }'
```

**Online Booking**:
```bash
curl -X POST http://localhost:3000/api/book \
  -H "Content-Type: application/json" \
  -d '{
    "doctorId": "doc_manual", 
    "slotId": "s1", 
    "patientName": "Jane Online", 
    "type": "ONLINE"
  }'
```

**Paid Priority**:
```bash
curl -X POST http://localhost:3000/api/book \
  -H "Content-Type: application/json" \
  -d '{
    "doctorId": "doc_manual", 
    "slotId": "s1", 
    "patientName": "Richie Rich", 
    "type": "PAID"
  }'
```

**Emergency (Will preempt if full)**:
```bash
curl -X POST http://localhost:3000/api/book \
  -H "Content-Type: application/json" \
  -d '{
    "doctorId": "doc_manual", 
    "slotId": "s1", 
    "patientName": "Emergency Doe", 
    "type": "EMERGENCY"
  }'
```

### 3. Check Schedule
```bash
curl http://localhost:3000/api/doctors/doc_manual
```
